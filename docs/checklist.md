# 云端 Claude Code 环境核查清单

以后加设备、换 SSH 配置或重建服务时，我会从**发生变化的入口**开始复查。换家庭电脑，先看第三组的客户端和连接来源；把手机会话改成新的启动方式，先看第二组的进程与服务。每次都留一项正常任务作对照，免得把服务离线误记成权限限制生效。

### 1. 服务端账户与权限

- [ ] 以独立工作账号运行 Claude Code 和 `code-server`。从实际会话核对 UID、主组和附加组。
- [ ] 核查 `/etc/sudoers`、其包含的规则及组授权，确认工作账号没有项目用不到的管理员权限，尤其是 `NOPASSWD: ALL`。
- [ ] 核对管理员及其他用户家目录的所有者、所属组与访问权限。采用 `0750` 时确认工作账号不在获授权的组里。
- [ ] 如使用 Tailscale，将本机守护进程管理接口限给所需管理身份。若借助 `tsadmin` 和 systemd drop-in 管理目录权限，服务重启后复查，管理员仍应能管理节点。
- [ ] 登录历史、系统日志保留给审计人员。核对本机实际日志后端，确认工作账号的可读范围，检查轮转后仍按预期写入、读取。

### 2. 进程、网络与同机业务

- [ ] 对实际启用的 `code-server`、命令行桥接、手机续聊和 WebDAV 分别核查 `ProtectProc`、`NoNewPrivileges`、`ProtectSystem`、`PrivateDevices` 与所需的路径限制。
- [ ] 手机续聊从受限服务启动。管理员所有的设置文件可按需设为 `0440 root:claudeops`，父目录也须由管理员控制。
- [ ] 按实际工作 UID 和目的地核对 nftables 出站策略，覆盖所用的 IPv4、IPv6、组网和同机转发入口，并保留工作所需 DNS。新连接和策略重载后再看一次实际效果。
- [ ] 同机业务目录按需设置具名 ACL，同时验证工作账号和原业务账号的有效权限。
- [ ] 盘点并停用已经迁出的旧面板、测试服务和端口映射。保留仍有使用者的路径。

### 3. 传输、其他远程开发连接与共享盘

- [ ] 如为性能调整 BBR 或排队策略，记录线路、时段和负载，在相近条件下对照传输结果。
- [ ] 隧道账号采用独立凭据，仅允许所需本地转发。核对 `AllowTcpForwarding local`、`PermitOpen` 和终端、Agent、X11 等额外能力的生效设置。
- [ ] 办公、家庭设备上的每个远程开发工具分别核对。用 `ssh -G` 看新连接的配置，正常断开并重连后，核对实际连接来源。
- [ ] 无需接受组网入站的设备可使用 Shields Up。保留远程桌面的设备，在组网策略和设备防火墙中列清获准的来源及服务。
- [ ] WebDAV 仅监听回环地址，启用认证，只导出所选项目。Windows 挂盘后检查匿名读取被拒绝，并从两端读写一份临时文件。

### 4. 浏览器与日常使用

- [ ] 按需核对 `code-server` 与 Claude Code 的产品遥测设置，并保留运维所需的服务日志。
- [ ] 专用 Firefox Profile 打开编辑器，核对当前 Profile、扩展、登录账号和站点权限。
- [ ] 网页 OAuth 授权也在选定的工作 Profile 中完成，核对域名、账号和授权范围。
- [ ] 公开项目的 Git 邮箱采用所选公开地址。对外分享日志、截图和会话时，只对导出的副本脱敏。
- [ ] 手机端按需管理 App 权限并验证续聊。定期核对远程项目的实际连接路径。`Z:` 中的 `.exe`、`.lnk`、`.url` 会作用于打开它们的本机，先核对来源和用途再打开。
