# 用红蓝两种视角复核自己的 Claude Code 环境

做完上面的清单，有些项已经有了明确结果，有些还差证据。后一类就适合交给 Opus 一起复核。例如，已经拿到了 `ssh -G` 的输出，却还不知道旧会话是否重连，就请它指出还缺哪一端的记录。下面的七个阶段把前文的九步按复核任务合并；填好环境参数，从清单里那个尚未解决的问题开始即可。

```text
我在自己的 Ubuntu 服务器上运行 code-server 和 Claude Code。请用红蓝两种视角，帮我审阅下面这套云端工作环境。我会提供已脱敏的配置和本机检查结果。红方提出值得质疑的假设，蓝方说明怎样核对、怎样收紧，以及正常工作如何验收。

一、我的基础环境参数
· 服务器：<版本及 SSH 主机别名>
· 管理员：<管理账号；保留原有管理入口>
· 工作账号和目录：<例如 claudeops、/srv/claude-workspaces>
· 客户端入口：<办公、家里、手机分别用什么；已有隧道或代理只填必要说明>

二、检查边界
· 先根据我提供的材料列出疑点，未知项标为“待核实”。
· 修改建议要写清影响和还原办法，保留可用的管理员会话及审计日志。
· 举例只用无敏感内容的标记文件。报告中省略真实地址、密钥、口令和令牌。
· 标明操作位置。管理员终端、网页终端、手机接回的会话和 Windows 本机应分别记录。

三、按七个阶段复核

阶段 1｜只读体检
对照工作账号的 sudo 授权、服务启动身份、目录权限和已知客户端清单。
把“配置允许什么”和“本次实际观察到什么”分列。给每个疑点指出仍缺哪一项证据。

阶段 2｜权限收口与网络边界
检查工作账号是否确实需要 sudo、组网控制接口、登录历史，以及通往其他业务的网络访问。
根据已有访问策略，用文字列出应允许和应拒绝的方向；标明哪些管理员、监控或 DNS 功能需要保留。

阶段 3｜网页服务与手机 Remote Control
对照两个入口的服务单元和实际启动的进程。核对 User、NoNewPrivileges、ProtectProc、配置文件所有者和项目目录。
解释配置变更何时对新进程生效；保留一次网页编辑和一次手机续聊作为功能对照。

阶段 4｜SSH 隧道和线路性能
分别核对办公与家庭客户端实际采用的主机别名、账号、转发目标。把 ssh -G 的配置结果与新会话记录分开。
列出隧道专用账号需要的最小转发权限。若同时更换线路与拥塞控制，测速结果只归到这一组条件。

阶段 5｜WebDAV 与 Windows 盘符
指出 WebDAV 的导出根、监听地址、认证方式及符号链接处理。用两端都可以修改的普通文本文件验证读写。
再用工作区以外的无敏感标记做范围对照。写明盘符位于哪一端、实际文件保存在哪一端。

阶段 6｜专用浏览器与启动入口
核对工作配置、工作所需扩展、站点权限与启动快捷方式。指出哪些设置只影响本地浏览器。
给出一次从桌面打开编辑器、访问工作目录的功能检查。区分页面可读取的属性与实际传出的数据。

阶段 7｜目录 ACL、个人信息与最终验收
检查获准审阅的项目目录和准备对外分享的副本。核对 ACL、Git 作者配置和副本中的标识，保留原始审计记录。
每个入口给出一个应当成功的正常任务及一个应当被拒绝的无害对照。报告格式为：
入口｜运行身份｜预期｜实际证据｜结论或待核实项。
```
